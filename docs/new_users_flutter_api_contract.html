carland_auth — Flutter API contract

NewUsers flow for the new app. Base URL: https://digital-innovation.agency/auth/server · Header on almost all calls: Accept-Language: az | en | ru

Overview Flow auth createAndSend verify setPinCode login refresh Errors / locks Checklist

1. Overview

  • NewUsers base: /api/v1/newUsers
  • Legacy (old app only): /api/v1/users + /api/v1/otp — do not mix with NewUsers.
  • authToken — used in /auth and OTP steps (JSON body, not Bearer). TTL ~6 minutes.
  • pinSetupToken — returned only by /otp/verify; used only in setPinCode.
  • purpose — lives in JWT claims. Client may send purpose: "RESET" only on /auth. Do not send purpose query on setPinCode.
  • Drive UI from next: SEND_OTP | PIN_CHECK | VERIFY_OTP | SET_PIN

2. Happy paths

Register / first-time (no PIN yet)

1. POST /auth                 → next=SEND_OTP, authToken
2. POST /otp/createAndSend    → next=VERIFY_OTP, authToken
3. POST /otp/verify           → next=SET_PIN, pinSetupToken
4. PUT  /setPinCode           → { "status": "PIN_SET" }
5. POST /login                → accessToken + refreshToken

Existing user (PIN already set, status ACTIVE)

1. POST /auth  → next=PIN_CHECK, authToken
2. POST /login → accessToken + refreshToken

Forgot PIN

1. POST /auth { purpose: "RESET" } → next=SEND_OTP
2. createAndSend → verify → setPinCode → login
   (RESET setPin revokes other devices' refresh sessions)
Important: User who verified OTP but left before setPin (status OTP_VERIFIED) gets next=SEND_OTP on next /auth — not PIN_CHECK.

Limits

  • Max 3 SMS / 15 min per phone → phone lock ~5 min
  • IP abuse → IP lock 24 h
  • OTP TTL: 3 minutes

3. Error envelope (all NewUsers locks / errors)

{
  "error": "LOGIN_LOCKED",
  "message": "localized text",
  "timeStamp": "2026-08-10T12:00:00",
  "status": 429,
  "lockedUntil": "2026-08-10T12:05:00",
  "remainingSeconds": 240,
  "retryAfter": 240
}
FieldWhen
errorMachine code (OTP_INCORRECT, WEAK_PIN, LOGIN_LOCKED, …)
messageHuman text (language from Accept-Language where applicable)
lockedUntilSet on lock / rate-limit only
remainingSecondsSeconds left — decreases on each poll; do not restart from full duration client-side if server returns a new value
retryAfterSame as remainingSeconds (alias)
Flutter countdown: Prefer server remainingSeconds / lockedUntil on every 429. If user retries while locked, server returns the time left (e.g. 240), not a fresh 300.

APIs with lock + countdown

  • POST /auth — rate limit
  • POST /otp/createAndSend — cooldown / phone lock / IP lock
  • POST /otp/verify — OTP_VERIFY_LOCKED
  • POST /login — LOGIN_LOCKED

4. Flutter checklist

  • Persist authToken for OTP steps; after verify switch to pinSetupToken
  • UI routing from next only
  • After PIN_SET always call login
  • Require deviceId on login
  • Global 429 handler with countdown UI
  • Never log OTP or PIN
  • Refresh via legacy /api/v1/users/refresh
